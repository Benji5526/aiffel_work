# PRD: Gina - AI 여행 상담원 (MVP)

## 무엇

Gina는 해외 여행·관광회사의 AI 고객 상담원이다. 고객이 DM으로 여행 관련 문의를 보내면, 의도를 파악하고 그동안 알아낸 고객 정보를 바탕으로 전문 상담원 톤으로 답한다.

```
고객 메시지
   │
   ▼
Gina (의도 분석 + 정보 추출) ── 구조화 출력 1회 호출
   │
   ├─▶ 고객 메모리(SQLite)에 병합 저장
   │
   ▼
Gina (페르소나 반영 답변 생성)
   │
   ▼
고객에게 응답
```

이번 MVP는 실제 DM 채널(Instagram/X/Threads) 대신 터미널 CLI를 임시 채널로 써서, 핵심 로직(의도분석·메모리·페르소나·답변생성)만 먼저 완성하고 검증하는 단계다. 플랫폼 연동, 미디어 라이브러리, 관리자 승인 화면, 예약/결제는 다음 단계로 미룬다.

## 기능

| 기능 | 포함 여부 | 비고 |
| --- | --- | --- |
| 의도 분석 (6종 분류) | ✅ | travel_planning/tour_price/hotel_recommendation/itinerary_question/media_request/general_inquiry |
| 고객 정보 추출 (목적지/날짜/인원/관심사/예산) | ✅ | 의도 분석과 한 번의 호출로 통합 |
| 고객별 메모리 (세션 간 지속) | ✅ | SQLite, 별도 프로세스로 재실행해도 유지 |
| 페르소나 기반 답변 생성 | ✅ | 전문 여행 상담원 톤, 실제 Gemini API |
| API 키 없을 때 목(mock) 모드 | ✅ | 규칙 기반 자동 대체, 코드 수정 불필요 |
| 실제 DM 채널(Instagram/X/Threads) 연동 | ❌ | 공식 API 조사 후 별도 change |
| 자사 미디어 라이브러리 (사진/영상 검색·전송) | ❌ | 다음 단계 |
| 관리자 승인 화면 | ❌ | 다음 단계 |
| 예약 / 결제 | ❌ | 이 MVP의 범위 밖 (사람에게 넘김) |

## 동작

1. **의도 분석 + 정보 추출** (`services/extractAgent.js`) — 고객 메시지 하나를 구조화 출력 1회로 분석해 의도와 목적지/상품/여행일/인원/관심사/예산을 뽑는다. 언급 안 된 필드는 항상 null.
2. **메모리 병합** (`services/memoryService.js`) — 추출된 값 중 아직 비어 있는 필드만 채운다. 이미 알고 있는 값은 이후 메시지가 그 정보를 반복하지 않아도 지워지지 않는다. 고객은 `(platform, platform_user_id)`로 식별되며, 처음 보는 조합이면 새 레코드를 만든다.
3. **답변 생성** (`services/replyAgent.js`) — 페르소나 + 지금까지 알고 있는 고객 정보 + 최근 대화 이력을 반영해 자유 형식 응답을 만든다.
4. **목 모드 자동 전환** (`services/mock.js`) — `GEMINI_API_KEY`가 없으면 위 세 단계 모두 규칙 기반으로 대체되어, 실제 API 호출 없이 흐름만 검증할 수 있다. 키가 채워지면 코드 수정 없이 자동으로 실제 호출로 전환된다.
5. **CLI 채널** (`cli.js`) — `node cli.js chat <고객이름>`으로 대화를 시뮬레이션. 프로세스를 새로 실행해도 같은 고객이름이면 이전 대화 기억이 이어진다.

## 규칙

Gina가 절대 하지 말아야 할 것 (`persona-gina-travel.md` 기준):

- **가격·재고·일정을 지어내지 않는다.** 확실하지 않으면 "담당 상담사가 확인 후 안내"라고 답한다.
- **예약·결제를 직접 처리하지 않는다.** 이 MVP는 상담(정보 제공)까지만 — 요청이 오면 담당 직원에게 연결한다고 안내한다.
- **AI라는 사실을 숨기지 않는다.** 직접 물어보면 정직하게 답하고, 사람인 척하지 않는다.
- **아직 없는 기능(사진/영상 전송)을 있는 척하지 않는다.** 담당 직원이 이어서 안내한다고 답한다.

플랫폼 연동 시 지킬 원칙 (원래 설계 문서 기준, 아직 구현 전이지만 방향은 확정):

- 공식 API·정상적인 OAuth만 사용한다. CAPTCHA 우회, bot detection 회피, rate limit 우회 같은 자동화 탐지 회피 기술은 목표로 삼지 않는다.
- Human-in-the-loop — 초기에는 AI가 판단하고 직원이 확인 후 전송하는 방식으로 간다.
- 플랫폼별 코드는 Gina 코어와 분리한다 (Platform Adapter 패턴), 코어를 다시 짜지 않고 플랫폼을 추가/교체할 수 있게.
